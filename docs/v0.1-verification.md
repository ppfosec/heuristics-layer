# V0.1 verification record

Run `npm run verify:v0.1` from a clean checkout. The command type-checks, lints, runs the test suite, exports schemas, builds the package, executes the vertical-slice demo, executes the three-condition evaluation, and inspects the npm package contents.

| Definition of done | Authoritative evidence |
| --- | --- |
| Coherent repository architecture | `docs/architecture.md`, seven ADRs, package exports, CLI, and build output |
| Public/private boundary documented | `docs/private-corpus.md`, ADR 0007, `SECURITY.md`, and server-side integration guidance |
| Transcript import | `Workflow.importTranscript` and the YAML timestamp regression test |
| Structured notes | `InterviewNotes` schema, `generateNotes`, prompt adapter, and synthetic fixture |
| Candidate extraction | `extractCandidates`, heuristic schema, and provider-boundary tests |
| Provenance | Required source interview and excerpts, approval identity/time, round-trip and workflow tests |
| Challenge | Challenge schema, prompt, lifecycle transition, fixture, and workflow test |
| Human review state | Explicit CLI review action; approval requires reviewer, reason, timestamp, and expert confidence |
| Approved storage and stable IDs | Strict Markdown sources, ID regex, SemVer, duplicate checks, and public examples |
| Corpus compilation | `compileCorpus`, normalized JSON, source hash, relationship validation, and tests |
| Retrieval | Weighted lexical retrieval with domain filter, IDs, versions, scores, matched terms, reasons, and tests |
| LLM assembly | `assembleReasoningContext`, structured observable output contract, and provider-neutral `ReasoningModel` |
| End-to-end demo | `npm run demo` writes interview, notes, candidates, challenges, reviews, approved Markdown, corpus, retrieval trace, and assembled context |
| Initial evals | Seven schema-valid cases; `npm run eval` compares base, generic GRC prompt, and retrieved heuristics; blind review and expert-grade schemas and CLI commands support human scoring |
| Passing tests | `npm run check` covers schemas, authoring, lifecycle, provenance, compiler, retrieval, briefings, rubric, provider adapter, examples, dataset, and eval delta |
| Strong documentation | README, thesis, research, architecture, interview, authoring, private corpus, retrieval, integration, evaluation, security, contribution, and future UI guides |
| Model independence | `StructuredGenerator`, `PromptModel`, and `ReasoningModel`; no provider SDK or orchestration framework dependency |
| Private corpora remain private | Explicit filesystem input, no telemetry or hidden network calls, server-side deployment boundary |
| Public examples | Three synthetic interviews, four synthetic approved example heuristics, and seven synthetic eval cases |
| Another developer can use it | Quick start, CLI reference, integration example, generated JSON Schemas, package typings, CI, and contribution instructions |

The deterministic fixture validates the system and evaluation mechanics. It does not establish general model improvement or encode Pierre-Paul Ferland's actual expert corpus. Real private interviews and blind expert grading are the next evidence layer, not a condition the brief assigns to the synthetic v0.1 milestone.
